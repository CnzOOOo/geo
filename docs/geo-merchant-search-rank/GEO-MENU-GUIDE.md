# GEO 菜单使用说明

## 使用前准备

1. 使用管理员账号登录 GEO 运营后台。
2. 先建立商家主档，再录入问题库、知识库和文章。
3. 发布平台前，先在 Wechatsync 环境检查页确认 Chrome 扩展已连接。
4. 所有发布任务默认只创建草稿，不会直接正式发布。

## 商家主档

菜单：`GEO运营 -> 商家主档`

商家主档是问题库、知识库、文章、发布和监测的公共基础。

操作步骤：

1. 点击“新增”，填写商家名称、类目、城市、地址、电话、营业时间。
2. 补充官网、小程序、Logo 和一句话简介。
3. 保存后状态默认为 `草稿`，确认资料无误后改为 `启用`。
4. 商家状态变更后，后续新增的问题和知识会自动归属该商家。

状态说明：

| 状态 | 说明 |
|---|---|
| 0 草稿 | 尚未启用，不参与监测 |
| 1 启用 | 可被问题库、文章、发布任务使用 |
| 2 停用 | 停止参与新任务，历史数据保留 |

## 问题库

菜单：`GEO运营 -> 问题库`

问题库用于维护用户可能向 AI 搜索提出的真实问题。

建议按以下类型维护：

| 类型 | 示例 |
|---|---|
| BRAND 品牌词 | XX咖啡 怎么样 |
| HOW 怎么做/是否 | XX咖啡 可以停车吗 |
| WHICH 推荐 | 徐汇区 适合办公的咖啡店 |
| COMPARE 对比 | XX咖啡 和 YY咖啡 哪个好 |
| AVOID 避坑 | 徐汇区 咖啡店 踩雷 |
| FAQ 常见问题 | XX咖啡 营业到几点 |

操作建议：

1. 每个商家至少维护 20 条问题。
2. 问题使用用户真实搜索习惯，不要堆关键词。
3. 按优先级 `1-5` 标记重点问题。
4. 问题状态建议保持 `启用`，只有不再监测的问题才停用。

## 知识库

菜单：`GEO运营 -> 知识库`

知识库是文章生成、AI 回答监测和 SEO 产物的事实来源。

每条知识建议包含：

- 事实名：例如“营业时间”
- 事实值：例如“周一至周五 09:00-21:00”
- 来源：官网、地图、点评、营业执照等
- 验证时间：确认事实最近一次核对时间

建议先录入：

1. 地址、电话、营业时间、休息日
2. 主营产品、价格、预约方式
3. 停车、地铁、外卖、会员
4. 营业执照、资质、获奖、媒体报道
5. 差异化事实：特色服务、适合场景、独特工艺

状态说明：

| 状态 | 说明 |
|---|---|
| 0 草稿 | 未验证，不建议用于正式内容 |
| 1 已验证 | 事实经过人工确认 |
| 2 已过期 | 事实已失效，需要更新 |
| 3 已禁用 | 不再使用，保留历史记录 |

## 文章工坊

菜单：`GEO运营 -> 文章工坊`

文章用于覆盖问题库中的重点问题，也是发布任务的内容来源。

操作流程：

1. 新增文章，选择关联商家和问题。
2. 填写标题、摘要和 Markdown 正文。
3. 保存后文章状态为 `草稿`。
4. 点击“提交审核”，进入审核流程。
5. 审核通过后，可以“发布到平台”或进入发布任务。

文章状态：

| 状态 | 说明 |
|---|---|
| 0 草稿 | 尚未提交审核 |
| 1 待审核 | 等待人工审核 |
| 2 已发布 | 已完成发布或进入发布任务 |
| 3 已下线 | 不再展示 |

## 发布渠道

菜单：`GEO运营 -> 发布渠道`

发布渠道用于配置文章可以发布到哪些平台。

目前支持：

- 知乎
- B站
- CSDN
- 简书
- 掘金
- 百家号
- 雪球
- 公众号
- 搜狐号
- 网易号
- 头条号
- 其他人工兜底平台

新增渠道时：

1. 选择商家和平台。
2. 渠道名称建议写“平台名 + 账号名”，例如“知乎-主账号”。
3. 启用 Wechatsync 桥接时，配置：

```json
{
  "wechatsyncEnabled": true,
  "token": "Chrome 扩展中的 Token",
  "wsPort": "9527"
}
```

4. 保存后，渠道状态应保持 `启用`。

## 发布任务

菜单：`GEO运营 -> 发布任务`

发布任务用于把文章发送到指定渠道。

操作步骤：

1. 点击“新增”，选择文章和渠道。
2. 任务状态默认 `排队`。
3. 如需立即执行，点击“创建并执行”。
4. 执行成功后，任务状态变为 `成功`，并记录外部草稿链接。
5. 失败任务会记录错误信息，方便重新执行。

任务状态：

| 状态 | 说明 |
|---|---|
| 0 排队 | 等待执行 |
| 1 发布中 | 正在调用发布链路 |
| 2 成功 | 已完成草稿创建或发布 |
| 3 失败 | 平台未登录、渠道配置错误或接口失败 |
| 4 人工 | 需要人工处理 |

## Wechatsync 环境检查

菜单：`GEO运营 -> Wechatsync 环境检查`

该页面用于检查发布链路是否就绪。

必须确认：

1. `CLI 已安装`：显示“是”。
2. `Token 已配置`：显示“是”。
3. `同步桥接`：Chrome 扩展设置中开启 `CLI / MCP 连接`。
4. `平台登录`：知乎、CSDN、简书等平台在 Chrome 中已登录。

页面按钮：

| 按钮 | 用途 |
|---|---|
| 重新检测 | 刷新 CLI 和 Token 状态 |
| 一键安装 | 安装 Wechatsync CLI |
| 检查更新 | 查询 CLI 最新版本 |
| 一键更新 | 更新 Wechatsync CLI |
| 打开扩展设置 | 打开 Chrome 扩展页面 |
| 检查平台登录 | 获取所有平台登录状态 |

## AI 回答监测

菜单：`GEO运营 -> AI 回答监测`

监测任务会把问题库中的问题发送到监测引擎，并记录 AI 回答。

操作流程：

1. 在“监测任务”中新增任务，选择商家。
2. 配置查询集，例如：

```json
[
  { "query": "上海 咖啡店 推荐" },
  { "query": "XX咖啡 怎么样" }
]
```

3. 配置执行周期：`DAILY` 或手动执行。
4. 点击“立即执行”，生成 AI 回答记录。
5. 在“AI 回答”列表检查是否提到商家、回答是否准确、引用来源是否真实。

重点复核：

- AI 是否提到商家
- 地址、电话、营业时间是否准确
- 引用链接是否真实存在
- 是否存在负面或错误信息

## 舆情事件

菜单：`GEO运营 -> 舆情事件`

舆情事件用于记录和处理差评、AI 答错、事实过期等问题。

新增事件建议填写：

```json
{
  "merchantId": "商家ID",
  "platform": "大众点评",
  "eventType": "差评",
  "title": "顾客反馈营业时间错误",
  "content": "原回答说营业到 22:00，实际 21:00 闭店",
  "sentiment": "negative",
  "severity": 4,
  "status": 0,
  "sourceUrl": "https://..."
}
```

处理流程：

1. `待处理`：发现异常后录入。
2. `处理中`：查证事实、修正知识库或页面。
3. `已闭环`：问题已修复。
4. `已归档`：完成总结，不再跟进。

严重级别建议：

| 级别 | 建议 |
|---|---|
| 1-2 | 普通评论，定期处理 |
| 3 | 影响推荐，当天处理 |
| 4-5 | 差评扩散或 AI 大面积答错，立即处理 |

## 效果实验

菜单：`GEO运营 -> 效果实验`

实验用于对比优化前后的 GEO 效果。

建议：

1. 先记录基线数据。
2. 建立对照组和实验组。
3. 上线知识库、文章或 SEO 产物后运行实验。
4. 对比 mention rate、citation rate、事实准确率和来源多样性。

## 常见操作顺序

推荐首次使用顺序：

```text
商家主档 -> 问题库 -> 知识库 -> 文章工坊 -> 发布渠道 -> 发布任务 -> AI 回答监测 -> 舆情事件
```

## 注意事项

- 所有文章和知识必须基于真实事实。
- 不编造评价、不诱导 AI、不制造虚假背书。
- 发布任务默认只创建草稿，确认无误后再手动正式发布。
- AI Key 未配置时，AI 生成和自动监测不可用，可先使用人工版本。
